# ArrayLab – Array Declaration Compiler

ArrayLab is a web-based educational compiler project that demonstrates the basic phases of compiler design using C, Flex, and Bison. It allows users to enter C array declarations, compile them, view compiler messages, inspect the symbol table, and visualise a syntax tree through a simple web interface.

## Features

- **Source Code Editor:** Enter C array declarations in the browser.
- **Example Programs:** Load predefined examples for testing.
- **Lexical Analysis:** Recognise keywords, identifiers, numbers, and special symbols using Flex.
- **Syntax Analysis:** Validate array declarations using Bison grammar rules.
- **Semantic Validation:** Check array sizes against the supported constraints.
- **Compiler Output:** Display compilation results and error messages.
- **Symbol Table:** View declared array names, data types, and sizes.
- **Syntax Tree Visualisation:** Display a visual hierarchy of array declarations.
- **Local Web Server:** Communicate with the compiler through a C-based HTTP server.

Ensure the tools are available in your MSYS2 UCRT64 terminal.

## Installation and Setup

### 1. Open the project

Open the `ArrayLab` folder in Visual Studio Code.

### 2. Open the MSYS2 UCRT64 terminal

Navigate to your project directory. For example:

```bash
cd /c/Users/USER/Desktop/ArrayLab
```

Replace `USER` with your Windows username if necessary.

### 3. Build the project

Run:

```bash
make
```

This uses the `Makefile` to generate the parser and lexer source files and compile the executables.

If you need a clean rebuild, run:

```bash
make clean
make
```

### 4. Start the server

Run:

```bash
./server.exe
```

Keep the terminal open while using the application.

### 5. Open the application

Open the following address in your browser:

**http://127.0.0.1:8080**

If you have made frontend changes, refresh the browser using `Ctrl + F5`.

## How to Use

1. Open ArrayLab in your browser.
2. Enter an array declaration in the source code editor or choose a predefined example.
3. Click **Compile Code**.
4. Review the compilation pipeline and compiler output.
5. Inspect the symbol table for successfully processed declarations.
6. View the visual syntax tree generated by the frontend.
7. Try invalid declarations to observe the errors reported by the compiler.

## Sample Input

```c
int marks[5];
float prices[3];
char letters[10];
```

These declarations define three arrays with different data types and sizes.

## Sample Test Cases

| Test case | Input | Expected behaviour |
|---|---|---|
| Valid declaration | `int marks[5];` | Successful compilation |
| Multiple declarations | `int marks[5]; float prices[3];` | Process both declarations |
| Zero-sized array | `int marks[0];` | Semantic error |
| Missing semicolon | `int marks[5]` | Syntax error |
| Missing array size | `int marks[];` | Syntax error |
| Invalid character | `int marks[5]@;` | Lexical error |

Actual output depends on the implemented compiler rules.

## Compilation Workflow

1. The user enters source code through the web interface.
2. The C server receives the source code.
3. Flex analyses the input and recognises tokens.
4. Bison checks the token sequence against the array declaration grammar.
5. Semantic validation checks the supported array-size constraints.
6. The compiler returns its output to the web interface.
7. JavaScript displays the results and generates a visual syntax tree.

## Limitations

- The compiler supports a limited subset of C array declaration syntax.
- It is not a complete C compiler.
- Semantic checks are limited to the rules implemented in the parser.
- The syntax tree is generated visually by JavaScript from the source text; it is not the actual parse tree generated by Bison.
- The server is designed for local educational use rather than production deployment.
